## Knowledge 层 Rules

### Rule: 用户可见文本必须 i18n

**Rule ID**: i18n-and-text-boundaries/rule-1
**规则**: 任何返回给前端的错误消息 / Controller 响应字段 label / 日志中的用户可见
文案必须走 i18n 层（`MessageSource` / `@Message("key")`）
**适用**: `src/main/java/**/controller/**/*.java` + `src/main/java/**/*Exception*.java`
**Evidence**: evidence.md#rule-1
**Confidence**: high
**Status**: active
**violation_test**: must_not_use_pattern
**pattern**: `"[一-龥]+"`

### Rule: i18n key 必须 `module.submodule.message` 三级格式

**Rule ID**: i18n-and-text-boundaries/rule-2
**规则**: i18n key 三级命名（如 `order.refund.exceed_limit`），不允许单级 key
**适用**: `src/main/resources/i18n/messages_*.properties`
**Evidence**: evidence.md#rule-2
**Confidence**: high
**Status**: active
**violation_test**: must_not_use_pattern
**pattern**: `^[a-z]+\\s*=`

## Memory 层 Constraint（long-term）

```yaml
---
id: constraint-i18n-boundaries
status: active
source: platform_limit
owner: i18n-team
applies_to:
  paths:
    - "src/main/java/**"
    - "src/main/resources/i18n/**"
  modules:
    - i18n
last_verified: {{today}}
expiry_after_days: 365
---
```

### Constraint

所有**用户可见**文本（Controller 响应 / 错误消息 / 前端 label / 邮件 / 短信）
必须通过企业 i18n SDK；后台日志 / 调试输出允许英文硬编码。

### Why It Exists

企业业务多市场运营（CN / HK / MY / SG / JP），硬编码中文会让其他市场降级。
i18n 框架由平台部统一维护，任何绕开都会进入"i18n 债务清单"季度治理。

### Allowed Workaround

无。新功能一律走 i18n。历史硬编码存量由 `java-backend-i18n-refactor` / `costasset-i18n-phase2` 治理。

### Violation Cost

每条新引入的硬编码文本进入"i18n 债务清单"，季度治理时回滚作者姓名。
