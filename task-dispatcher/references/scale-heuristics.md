# 派发规则与规模直觉

## 派发规则

| 子任务类型 | Agent 类型 | 何时派发 |
|-----------|-----------|---------|
| 文件搜索 / 代码探索 | `Explore` agent | 始终派发 |
| 调研 / web search / 文档抓取 | `general-purpose` agent | 始终派发 |
| 小型代码变更（1-3 文件，spec 明确） | `general-purpose` agent + 详细 prompt | spec 无歧义时派发 |
| 复杂代码 / 架构决策 | 主 agent（自己） | 不派发 — 需要判断力 |
| 面向用户的回答 / 建议 | 主 agent（自己） | 不派发 — 需要用户上下文 |

## 规模直觉

| 子任务预估耗时 | 策略 |
|--------------|------|
| < 10 秒 | 不值得派发，直接做 |
| 10 秒 ~ 2 分钟 | 派发到 background agent |
| > 2 分钟 | 派发 + 同时启动其他工作 |

---

## 批次划分原则

派发多个 Agent 时：
- **每个文件最多 1 个 Agent** — 绝不让两个 Agent 编辑同一个文件
- **多语言文件例外**：一个 Agent 可以处理所有 locale 文件（各语言文件相互独立）
- **如果任务需要修改 10 个以上文件**：按目录拆分为子批次
- **Agent 数量 vs. 开销**：预计耗时 < 10 秒的任务，不要启动 Agent — 直接内联完成。Agent 启动开销约 15-30 秒。
