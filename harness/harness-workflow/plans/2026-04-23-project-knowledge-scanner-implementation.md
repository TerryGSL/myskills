- [ ] **Step 1: 写入文件**

将以下内容写入 `harness-workflow/references/project-scanner.md`：

```markdown
# Project Knowledge Scanner — Runtime Reference

> 本文档是 harness-workflow 的 `--scan-project` / `--rescan` / `--partial-rescan` 执行规范。
> Spec 推导见 `specs/2026-04-23-project-knowledge-scanner-design.md` §Scanner Pipeline。

---

## 1. 触发方式

| 命令 | 含义 | 场景 |
|------|------|------|
| `/harness-workflow --scan-project` | 首次扫描（生成 INDEX + 5 domain 知识库）| `--init` / `--adopt` 后自动串联；或用户显式调用 |
| `/harness-workflow --rescan` | 全量重扫（28 min full pipeline）| 项目重大演化 / INDEX 过旧 |
| `/harness-workflow --partial-rescan <domain>` | 单 domain 重扫（≤ 10 min）| drift 修复 / 单领域演化 |
| `/harness-workflow --apply-knowledge-answers` | 处理 TODO.md 用户答案（见 Phase 5）| 用户填完 TODO.md 后 |

---

## 2. 总 Scan Budget 硬上限

| 项 | 上限 | 依据 |
|---|---|---|
| 总 wall-clock | 28 min | 平衡完整性与响应性 |
| 每 scanner full file read | 24 个 | 足够采样，不溺水；`rg` / symbol index 无限 |
| 总 TODO 数（呈现用户）| ≤ 8 | 用户明示"尽量少" |
| manifest.md 大小 | 140 行 | retrieval 质量崩塌阈值 |
| evidence.md 大小 | 220 行 | audit 用，不注入 |
| 最大激活 domain | 5 | 超出说明分类有问题 |

超 28 min → 当前 Phase 完成后 BLOCKED，用户决定延长或接受 partial 结果。

---

## 3. 5-Phase Pipeline

### Phase 1: Scout（8 min，主 coordinator 自跑）

**不**派 subagent。主 agent 直接：

1. `ls` / `rg` 快速遍历，不做全文 AST 分析
2. 从 `.harness-context.json` 读技术栈（language / framework / packageManager）
3. 识别模块边界：
   - top-level package 树
   - 主要目录（src/, lib/, modules/, 等）
4. 探测 domain 激活信号：

| Domain | 激活条件 | 始终激活 |
|--------|---------|---------|
| `style-and-structure` | 总是 | ✅ |
| `internal-components` | 总是 | ✅ |
| `exception-and-error-contracts` | 发现 `throw` / `catch` / 异常类定义 > 10 处 | — |
| `integrations-and-sdk-usage` | 发现 SDK client / adapter package / HTTP client wrapper | — |
| `i18n-and-text-boundaries` | 发现 `messages_*.properties` / `i18n` helpers / translation bundles | — |

5. 输出 `scout-report.json` 临时字段：写入 `.harness-status.json.scoutReport`

```json
{
  "scoutReport": {
    "tech_stack": "java/spring-boot",
    "total_files": 487,
    "module_boundaries": ["com.acme.core", "com.acme.api", "com.acme.integrations"],
    "domain_activation_signals": {
      "style-and-structure": "always",
      "internal-components": "always",
      "exception-and-error-contracts": "strong (142 throw sites, 18 custom exception classes)",
      "integrations-and-sdk-usage": "medium (3 SDK clients under com.acme.integrations)",
      "i18n-and-text-boundaries": "none (no resource bundles found)"
    },
    "active_domains": ["style-and-structure", "internal-components", "exception-and-error-contracts", "integrations-and-sdk-usage"]
  }
}
```

**失败**：Scout 异常 → BLOCKED，scanner 不跑。

---

### Phase 2: Parallel Domain Scan（12 min，N subagents 并行）

N = 激活 domain 数，max 5。每个 subagent 负责 1 domain。**并行派发**（见 harness-workflow 的 `dispatching-parallel-agents` pattern）。

每个 subagent 输入：
- `domain_name`: 5 个之一
- `applies_to_globs`: scout 给出的 domain boundary
- `scan_budget`: 24 files max read, 3 min wall-clock
- `prompt`: 来自 `harness-workflow/prompts/scanner-prompts.md` 对应 domain 的 prompt

每个 subagent 执行：
1. 用 `rg` / symbol index 在 applies_to_globs 里无限制搜索
2. 选 ≤ 24 个 representative 文件做 full read：
   - import count 高的核心模块
   - 最近改动的热点
   - 边界模块（adapter / controller / util）
3. 提取 convention 候选，按 confidence 分级：
   - **High**: ≥ 2 正例（核心模块）OR 1 正 + 1 反（deprecated pattern 边界）
   - **Medium**: 1 个强例子在核心模块
   - **Low**: 弱信号
4. 每条 convention 必须带 `file:line` + interpretation（一句话）
5. 输出：
   - `docs/harness/knowledge/<domain>/manifest-draft.md`: high confidence rules only
   - `docs/harness/knowledge/<domain>/evidence-draft.md`: 对应 evidence anchor
   - 结构化 medium TODO buffer（合并到 Phase 4）

Subagent 硬门（强制 prompt 前置，见 scanner-prompts.md）：
- 不扫 domain 边界外文件
- 不编造 convention（证据不足 → medium → TODO）
- 不照搬 legacy 坏风格（应标记 deprecated pattern，evidence 写反例）
- manifest-draft.md ≤ 140 行，超出必须挤掉 low-impact rules

**失败**：某 domain scanner 超时（>3 min） → 该 domain 标 `status: partial`，confidence 降级；不阻塞其他 domain。

## 2. Rule Status 四态运行时影响

| Status | 意义 | Stage -0.5 处理 | reviewer 行为 |
|---|---|---|---|
| `active` | 正常有效 rule | 加入 `knowledge_requirements`（binding）| 违反 → FAIL |

- `expired`：free_form_review rule 时间到期，rule 本身没过时，只是无法机器验证

对每个 manifest 的每条 Rule（仅 `violation_test` 为结构化 enum 的）：

1. 用 Rule 的 `violation_test` + `applies_to` glob，采最多 10 个 matched occurrences
