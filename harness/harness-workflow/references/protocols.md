# 行为协议（所有 Agent 通用）

> 本文件定义跨 Stage 的通用行为规范。各 team-* skill 引用本文件，不重复内联。

---

## 1. 反谄媚规则

AI 在审查、分析、决策时必须直接表态，禁止和稀泥。

**禁止用语**（出现即违规）：
- 「这个想法很有趣」→ 改为：说清楚好在哪里、差在哪里
- 「有很多种方式可以…」→ 改为：选一种，说为什么
- 「你可能想考虑…」→ 改为：「这样做有问题，因为 X」或「这样做可行，因为 Y」
- 「这可能行得通」→ 改为：根据现有证据判断行不行，缺什么证据就说缺什么
- 「我能理解你为什么这么想」→ 改为：如果想法有误，直接指出并解释

**必须行为**：
- 每个决策点表态：选什么、为什么、什么证据会改变你的判断
- 追问纪律：第一个回答通常是包装过的，追到具体细节再下结论
- 挑战前提：如果用户的前提假设有问题，直接指出，不要顺着说

---

## 2. 完成状态协议

每个 Stage 结束时，必须输出以下四种状态之一：

| 状态 | 含义 | 后续动作 |
|------|------|---------|
| `完成` | 全部步骤成功完成 | 进入下一 Stage |
| `完成_有顾虑` | 完成了，但有需要关注的问题 | 列出顾虑，进入下一 Stage |
| `阻塞` | 无法继续 | 触发升级协议 |
| `需要上下文` | 缺少关键信息 | 说清缺什么，等待补充 |

写入 STATE.json 时，更新 `stageOutcome` 字段。

---

## 3. 统一升级协议

**铁律：3 次尝试失败 → 停止 → 升级。** 替代各 Stage 分散的 max-loop 逻辑。

适用场景：Spec 审查修复、Codex 审查修复、QA bug 修复、安全漏洞修复。

升级报告格式：

```
⚠️ 需要决策

状态：阻塞
问题：[1-2 句具体描述]
已尝试：
  1. [方案及结果]
  2. [方案及结果]
  3. [方案及结果]
建议：[推荐的下一步]
```

**绝不允许**：超过 3 次仍在循环修复。宁可停下来问，不要盲目重试。

---

## 4. 经验沉淀

每个 Stage 完成前，快速反思：

- 这次有没有意外失败的命令？
- 有没有走了弯路后来才发现更好的路？
- 有没有发现项目特有的坑（构建顺序、环境变量、时序问题、认证方式）？

如果有，通过 `claude-mem` 记录一条 operational-learning：
```
类型: operational-learning
关键词: [简短标签]
内容: [描述发现]
置信度: [1-10]
来源: Stage N / Round N
```

下次执行相关 Stage 时，自动搜索已有经验并应用。
